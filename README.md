# ЛогСклад — Demo MVP

Веб-приложение для логистических заявок и складских операций. Продуктовые сценарии и визуальное направление описаны в `docs/` и `references/`.

Статус реализации, ограничения и очередность следующих работ зафиксированы в [плане продолжения](docs/37_NEXT_IMPLEMENTATION_PLAN.md).

## Подготовка и запуск

Нужны Node.js 20.9+ и npm. Установите зависимости и создайте `.env.local`, скопировав `.env.example`:

```bash
npm install
cp .env.example .env.local
```

### Демо с сохранением данных

Запустите Docker Desktop. В `.env.local` оставьте `DESIGN_PREVIEW=false`, `DEMO_MODE=true` и локальный `DATABASE_URL` на порту `5435`. Значения из шаблона предназначены только для базы на `localhost`.

```bash
npm run db:up
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). База хранится в Docker-томе; повторный запуск seed не очищает и не перезаписывает существующие строки.

### Публичный статичный предпросмотр на GitHub Pages

В корне репозитория находится отдельный статичный интерфейс с вымышленными демо-данными. Он не подключается к базе и не отправляет формы. В настройках **Settings → Pages** источником публикации должен быть выбран **GitHub Actions**. Workflow собирает только файлы предпросмотра и автоматически публикует их по адресу [https://gevget.github.io/logsklad/](https://gevget.github.io/logsklad/) при каждом push в main.

В предпросмотре можно переключать пять ролей, открывать разделы, искать и фильтровать заявки, смотреть карточки перевозок и проходить форму создания заявки. Любые изменения существуют только в браузере и исчезают после перезагрузки. Полноценное приложение с серверными сценариями запускается локально по инструкции выше; GitHub Pages его серверную часть не заменяет.

### Просмотр интерфейса без базы

Для предпросмотра экранов установите `DESIGN_PREVIEW=true` в `.env.local` и запустите `npm run dev`. В этом режиме используются примеры, а изменения не сохраняются.

После работы остановите PostgreSQL командой `npm run db:down`. Docker-том с данными сохранится.

## Уже реализовано

- адаптивная оболочка и навигация пяти ролей;
- Demo identity в защищённой cookie, серверная проверка роли и прав;
- схема PostgreSQL/Drizzle, миграции и детерминированный seed;
- списки заявок с ролевой областью видимости, карточка заявки и история статусов;
- переходы статусов с транзакционной записью истории и журнала аудита;
- назначение водителя менеджером;
- создание заявки пошагово заказчиком или менеджером/администратором от имени выбранной компании, с сохранением черновика или отправкой на проверку;
- комментарии с разделением на клиентские и внутренние;
- in-app уведомления и отметка о прочтении;
- согласование базового расчёта, назначение доступного водителя и транспорта;
- подтверждение менеджером исходящего рейса со склада и оформление складом выдачи получателю;
- фиксация складских операций обработки с результатом, измерениями и фото;
- загрузка изображений и PDF в приватное хранилище: локальная папка для демо или Supabase Storage, проверка типа/размера и проверка прав перед просмотром;
- просмотр метаданных документов, демо-файлов и основных административных справочников.

В локальном демо (`DEMO_MODE=true`, вне production) файлы сохраняются в закрытой папке `.appdata/uploads` и отдаются только через проверяющий права серверный маршрут. Каталог исключён из Git. Для удалённого хранения укажите `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` и `SUPABASE_STORAGE_BUCKET` в `.env.local`; bucket должен быть создан в Supabase Storage. Реальные загрузки и полный цикл вложений ещё нужно принять по чек-листу. Админские списки, профили, справочники и журнал действий реализованы; полная приёмка ещё не завершена.

## Команды

```bash
npm run dev        # локальная разработка
npm run lint       # ESLint
npm run typecheck  # проверка TypeScript
npm run build      # production-сборка
npm run db:generate
npm run db:up
npm run db:down
npm run db:migrate
npm run db:seed
```

Сбросить данные можно на странице администратора `/admin/demo`: действие доступно только администратору в демо-режиме вне production и требует вручную ввести фразу `ВОССТАНОВИТЬ ДЕМО`. Очистка и восстановление seed выполняются в одной транзакции; привязанные локальные загрузки удаляются после успешного сброса. Также доступна консольная команда `npm run db:reset`; она требует `DEMO_MODE=true` и `RESET_DEMO_DATA=true` и заблокирована для production.

## Демо-пользователи

- Заказчик — `client@demo.local`
- Менеджер — `manager@demo.local`
- Водитель — `driver@demo.local`
- Склад — `warehouse@demo.local`
- Администратор — `admin@demo.local`

Это демонстрационные профили без паролей, не используйте такой переключатель идентичности в production.
