# 04 — ROLES AND PERMISSIONS

## 1. Цель
Зафиксировать роли и их разрешения.

Client-side hiding не считается защитой. Каждая mutation должна проверять разрешение server-side.

## 2. Роли

```ts
type UserRole =
  | "CLIENT"
  | "MANAGER"
  | "DRIVER"
  | "WAREHOUSE"
  | "ADMIN";
```

## 3. Client

### Может
- видеть свою компанию;
- видеть заявки своей компании;
- создавать заявку;
- редактировать draft;
- отправлять draft;
- добавлять документы / вложения;
- смотреть timeline;
- смотреть назначенного водителя, когда это разрешено состоянием;
- смотреть стоимость;
- смотреть уведомления;
- редактировать собственный профиль.

### Не может
- видеть заявки других компаний;
- назначать водителей;
- менять служебные статусы;
- менять фактические складские параметры;
- управлять пользователями;
- управлять тарифами;
- видеть внутренние комментарии.

## 4. Manager

### Может
- видеть все заявки;
- фильтровать и искать;
- открывать заявку;
- редактировать operational fields;
- назначать водителя;
- назначать транспорт;
- менять разрешённые статусы;
- добавлять internal и client-visible comments;
- редактировать стоимость;
- просматривать документы;
- видеть складские события;
- создавать заявку от имени клиента;
- ставить заявку на hold / issue.

### Не может
- менять system role пользователей;
- менять admin-only settings;
- удалять audit history.

## 5. Driver

### Может
- видеть только назначенные ему задания;
- видеть необходимые точки маршрута;
- видеть контакты по своему заданию;
- видеть релевантную информацию о грузе;
- менять только разрешённые driver statuses;
- загружать фото;
- прикреплять подтверждение доставки;
- добавлять комментарий к выполнению.

### Не может
- видеть чужие задания;
- видеть полную финансовую информацию;
- редактировать стоимость;
- менять поставщика / клиента;
- переназначать водителя;
- менять warehouse records;
- видеть внутреннюю admin-информацию.

## 6. Warehouse

### Может
- видеть ожидаемые на складе заявки;
- видеть грузы, находящиеся на складе;
- принимать груз;
- фиксировать фактическое количество мест;
- фиксировать фактический вес;
- добавлять фото;
- создавать warehouse operations;
- менять разрешённые warehouse statuses;
- отмечать выполнение услуг;
- выдавать груз.

### Не может
- менять коммерческие условия;
- назначать водителей;
- управлять пользователями;
- менять client company;
- удалять status history.

## 7. Admin

### Может
- управлять пользователями;
- менять роли;
- управлять компаниями;
- управлять справочниками;
- управлять услугами;
- управлять транспортом;
- видеть все заявки;
- видеть audit log;
- использовать demo reset / reseed tools, если они предусмотрены.

Даже Admin не удаляет audit history обычной UI-кнопкой.

## 8. Permission model
Создать централизованный слой:

```text
lib/permissions/
```

Пример API:

```ts
can(user, "order:view", order)
can(user, "order:update", order)
can(user, "order:assign_driver", order)
can(user, "warehouse:receive", order)
```

Не размножать role checks по десяткам компонентов, если можно использовать permission helper.

## 9. Visibility vs permission
Отдельно учитывать:
- можно ли выполнить действие;
- нужно ли показывать конкретные данные.

Driver может видеть адрес, контакт и груз, но не margin, invoice details и внутренние notes.

## 10. Client company scope
Client всегда ограничен `company_id`.

Если у компании несколько пользователей:
- они видят общие заявки компании;
- персональные настройки остаются личными.

## 11. Demo users
Seed должен содержать:
- минимум 2 Client users в разных компаниях;
- 2 Manager;
- несколько Driver;
- 2 Warehouse;
- 1 Admin.

Role Switcher может показывать по одному основному demo user на роль.

## 12. Permission matrix

| Action | Client | Manager | Driver | Warehouse | Admin |
|---|---:|---:|---:|---:|---:|
| View company/all relevant orders | ✓ | ✓ | assigned | relevant | ✓ |
| Create order | ✓ | ✓ | — | — | ✓ |
| Edit draft | ✓ | ✓ | — | — | ✓ |
| Submit order | ✓ | ✓ | — | — | ✓ |
| Assign driver | — | ✓ | — | — | ✓ |
| Driver execution status | — | limited | ✓ | — | ✓ |
| Receive at warehouse | — | limited | — | ✓ | ✓ |
| Edit price | — | ✓ | — | — | ✓ |
| Upload files | ✓ | ✓ | ✓ | ✓ | ✓ |
| Manage users | — | — | — | — | ✓ |
| Manage services | — | — | — | — | ✓ |
| View audit | — | limited | — | limited | ✓ |

## 13. Comments
Comment scope:
- `INTERNAL`;
- `CLIENT_VISIBLE`.

Client никогда не видит `INTERNAL`.
